Servidor sin pantalla (Raspberry Pi)

riars-server es RIARS sin ventana: reproduce, automatiza y emite por Internet, y se maneja desde el panel web, la API o agentes de IA. Funciona en Linux, en Windows y en una Raspberry Pi (64 y 32 bits).

Arrancarlo

riars-server --api-token MI_TOKEN --scan /home/pi/musica --bind 0.0.0.0

Sin --bind, el servidor solo acepta conexiones del propio equipo. Para usar el panel web desde el móvil u otro ordenador, pon --bind 0.0.0.0.

Archivos

Junto a la base de datos se guardan la programación de eventos (riars_schedule.json), la sesión (riars_session.json) y el token generado (riars_api_token). En Linux, la sesión y el token solo los puede leer el usuario del servidor: la sesión guarda la contraseña de Icecast. El servidor crea además en esa carpeta un archivo de bloqueo, riars.lock: si arrancas un segundo servidor sobre la misma base de datos, se detiene con el mensaje «Another RIARS process is using…» en vez de escribir los mismos archivos. Al reiniciar, el servidor sigue con la misma lista, en la misma posición, con el mismo volumen y la emisión conectada si lo estaba.

Seguridad

  • La API va por HTTP sin cifrar. Para manejar la emisora desde fuera de la red local, pon delante un proxy con HTTPS (por ejemplo Caddy o nginx) o usa una VPN.
  • Quien tenga el token controla la emisora: guárdalo como una contraseña.
  • La API y los agentes solo pueden usar archivos de las carpetas de la biblioteca y de las que indiques con --media-root. Las rutas de fuera se rechazan.
  • Un detector de intros con programa externo solo se puede elegir en la app de escritorio, nunca por la API.

Cuidar la tarjeta SD

RIARS está pensado para equipos modestos:

  • La base de datos escribe poco: una línea por elemento emitido.
  • La sesión solo se guarda cuando algo cambia, y la posición cada 30 segundos.
  • Lo que añade la automatización no provoca escrituras extra.

Consejo: para que arranque solo con la Raspberry Pi, crea un servicio de systemd que ejecute riars-server con tus opciones.
