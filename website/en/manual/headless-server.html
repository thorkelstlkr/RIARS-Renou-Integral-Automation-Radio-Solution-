Headless server

riars-server runs RIARS without a window on Linux, including a Raspberry Pi. It hosts the REST API, the WebSocket and the browser panel, and can run the MCP server for AI agents.

Starting it

From a terminal:

riars-server --port 3100 --api-token MY_SECRET_TOKEN --bind 0.0.0.0

Then open http://YOUR-SERVER:3100/ in a browser and enter the token. Without --bind, the server only accepts connections from the same machine; --bind 0.0.0.0 opens it to the network. If you do not give a token, RIARS generates one the first time and saves it in riars_api_token, next to the database.

Flags

FlagDefaultPurpose
--port3100Port for the API, WebSocket and panel
--bind127.0.0.1 (this machine only)Address the API listens on; 0.0.0.0 opens it to the network
--api-tokenfrom RIARS_API_TOKEN, else generated and saved in riars_api_tokenToken required by the API
--media-rootlibrary folders onlyFolder API and agent clients may play, add, scan and tag files from; repeatable. Library folders always count
--stream-hostanyIcecast server streaming may connect to, as host or host:port; repeatable
--cors-originnoneBrowser origin on another site allowed to call the API, e.g. https://panel.example.com; repeatable. The built-in panel needs none
--db-pathriars_library.dbPath to the library database
--scannoneFolder to add to the library; every library folder is rescanned in the background at startup
--no-sound-cardoffPlay on the internal clock, for servers that only stream
--devicesystem defaultOn-air sound card by name; if it is missing, the system default is used
--list-devices—List the sound cards and exit
--no-resumeoffStart fresh instead of restoring the last session
--mcp-stdiooffRun as an MCP server on standard input/output
--langenMessages: en, es, fr, de, pt or ca

--no-resume ignores the saved playlist, position, volume, crossfade and streaming. Without it, the server continues where it stopped.

Data files

The library database holds the tracks, categories, clocks, grid, campaigns and proof-of-play log. Next to it live riars_schedule.json (scheduled events), riars_session.json (the last session) and riars_api_token (the generated token). On Linux only the server's user can read the session and the token: the session holds the Icecast password. With --db-path /srv/riars/riars_library.db, all three are in /srv/riars/. The server also keeps a lock file, riars.lock, in that folder: a second server started on the same database stops with "Another RIARS process is using…" instead of writing the same files. The desktop app uses its per-user data folder; set RIARS_DATA_DIR to move that folder.

Security

  • The API is plain HTTP. To control the station from outside the local network, put an HTTPS proxy (such as Caddy or nginx) in front of it, or use a VPN.
  • Whoever has the token controls the station: keep it like a password.
  • The API and agents can only use files in the library folders and in the folders given with --media-root. Paths elsewhere are refused.
  • An external intro detector program can only be chosen in the desktop app, never over the API.

Raspberry Pi and SD cards

Use a good power supply and shut the machine down cleanly. SQLite runs in WAL mode to reduce writes, but a power cut can still corrupt a card. Keep backups of the data folder and export the CSV reports regularly. --no-sound-card is intended for a Pi that only streams; without it, RIARS tries to use a sound device.
